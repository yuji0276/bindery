## Data model
- action どのような操作を行うか
- mode nvimのinsert, zellijのtabを入れる
- tool ツールの名前
- key 割り当てられたキーバインド

定義元ジャンプなどの機能を後につけるためcolumn number,filepathなどもあとで入れるが、ここは拡張可能。衝突検知のために必要な最低限から始める

### key列の値域(型)

key列は行の集合から一つの値を導く写像として捉えることができる。ここではkeyのとりうる値域(型)について記述する。考慮しないといけないのは以下である。

- 同時押し or 順次押し
- 修飾キーを複数持つかどうか

これらを考慮して値域の集合を考える。構成は3段になる。
M := 修飾キーの語彙(Ctrl,Alt,Cmdなど。なんと綴るかは未確定)
B := 基底キーの語彙(t,=,leftなど。なんと綴るかは未確定)

1. 修飾キーの組み合わせ(Mの冪集合)
2. 1打鍵(修飾キーと基底キーの組み合わせ。Mのべき集合とBの直積)
3. 一つの割り当て(1打鍵の空ではない有限列)

例）

|入力|値域の元として|
|---|---|
|`Ctrl+Shift+t`|長さ1の列 `< ({Ctrl,Shift},t) >`|
|`<leader>ff`|長さ3の列 `< (∅,leader),(∅,f),(∅,f) >`|
|wezterm `SUPER` + `=`|長さ1の列 `< ({Super},=) >`|
|zellij `Ctrl+t` -> `n`|長さ2の列 `< ({Ctrl},t),(∅,n) >`|

空列を許さない理由：長さ0で何も押さないことになるから。キーとして意味をなさない。

### 競合判定

競合するかどうかの条件は以下の２つ。2つの条件がどちらも真になる時衝突していると言える

- モードが共存するかどうか
- 一方のキーが他方のキーの接頭辞であるかどうか

#### モードが共存するかどうか

２つの割り当てのモードが共存可能かどうかで決まる。toolは関係ない。

| 組| 競合するかどうか|共存可能か|
|--|--|--|
|(zellij tab, nvim normal)|競合しない|排他|
|(nvim normal,nvim insert)|競合しない|排他|
|(nvim normal,zellij normal)|競合する|**共存可能**|

共存関係の情報は各ツールの設定ファイルに存在しないためbindery.confのような設定ファイルを設けてそこに記述する方式を取れるようにする。現時点では個人のプロジェクトであるためコード上で共存可能かどうかを記述し、デフォルトの設定として扱うが、このツールが発展して多くの人に使われ、独自のツールにも対応できるようにbindery.confファイルに共存可能かどうかを示す設定ファイルから読み取れるようにする。

#### 一方のキーが他方のキーの接頭辞であるかどうか

`<leader>ff`と`<leader>f`は衝突するためこの条件が必要。
完全一致は長さの等しい接頭辞であるため、この条件に含まれる。同じキーが2つのツールに割り当てられているケースもここで拾われる。
